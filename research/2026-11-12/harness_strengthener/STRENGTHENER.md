## What the script does, requirement by requirement

### The exact basis (used by (a), (c), (d), (e))

The script does not enclose the float Gelfand–Tsetlin numbers. It rebuilds the same operator in exact rationals.

1. **Irreps.** For each (p,q) the Gelfand–Tsetlin patterns are rescaled, `e_i = sqrt(N_i) ξ_i` with rational `N_i`,
   so that E1, E2, F1, F2 have rational matrices and the invariant form is the positive rational diagonal
   `D = diag(N_i)`. `verify_irrep` then proves, in exact arithmetic, for every irrep used: weights of the four
   generators, `[E_i, F_j] = δ_ij H_i`, the Serre relations, `F_i` is the D-adjoint of `E_i`, the dimension equals
   dim(p,q), and the vector of weight (p,q) is killed by E1, E2. A unitary module of that dimension containing that
   highest-weight vector is the irrep. The GT formulas are therefore a proposal that is checked, not trusted.
2. **Multiplicity vectors.** For a ⊂ b ⊗ c the highest-weight vectors of weight a in V_b ⊗ V_c are the exact null
   space of (E1, E2) on that weight space, orthogonalised by rational Gram–Schmidt (no normalisation), norms `n_k`.
   Their number is asserted equal to the Racah–Speiser multiplicity, and Racah–Speiser itself is checked by
   `Σ_a N_a d_a = d_b d_c`.
3. **Basis functions.** `F_{b,c,a,k,l}(U,V) = tr(Φ_{a,k,l} ρ_b(U) ⊗ ρ_c(V))`, with Φ_{a,k,l} the G-map taking the copy
   of V_a generated by w_l to the copy generated by w_k. Peter–Weyl gives a diagonal Gram
   `G = (n_k / n_l) d_a / (d_b d_c)`; different (b,c,a,k,l) are orthogonal. `E_el = 3c(b) + 3c(c) + c(a)`.
4. **Multiplication by χ_f(U) = Tr U.** `χ_f(U) F_Φ = Σ_{b'} F_{J⁺(Φ⊗1)J}`, with `J : V_{b'} → V_b ⊗ V_f` an
   intertwiner and `J⁺ = J*/j` its left inverse (`J*J = j`). J is built exactly and its intertwining property is
   verified for all four generators. With `K_a[w]` the highest-weight vector of a' in (copy of V_a generated by w) ⊗ V_f,
   and `R[(a,k),k'] = ⟨K_a[w_{a,k}], J w'_{a',k'}⟩` (rational), the coefficient is
   `t[(a',k',l') ← (a,k,l)] = R[(a,l),l'] R[(a,k),k'] / (|K_a[w_l]|² · j · n'_{k'})`,
   and the form matrix is `Tf = G_target · t`. Tr V is the same on the c arm. `Re Tr U + Re Tr V` has form matrix
   `S = (Tf_U + Tf_Uᵀ + Tf_V + Tf_Vᵀ)/2`. Every number is a Fraction.

Exact checks run on every execution (any failure aborts):

- **Against the repo's independent exact Haar code.** At ECUT = 40/3 the new (E, G⁻¹S, G⁻¹M) and the repo's
  19-state (ENERGY, Gram⁻¹S, Gram⁻¹M) from `two_plaquette_19.matrices()` have equal traces of all 120 words of length
  ≤ 4 in the three operators, as exact rationals. c_plus = 43/3 is reproduced.
- **Commutation.** Multiplication operators commute. `[T_U,T_V] = [T_U,T_U†] = [T_U,T_V†] = [T_V,T_V†] = 0` holds
  exactly on every retained state whose first images stay inside P: 1271 identities at ECUT 50, 2381 at ECUT 60.
- **Norm balance on every retained state, boundary included.** `|T Φ|² = |T† Φ|²` for T_U and T_V, exactly, 1520 and
  2686 identities. The left side uses the complete outgoing column, including targets outside P; these are the
  entries that make M.
- **Character rule.** On the one-plaquette sector (c trivial) all coefficients equal 1 (47 and 54 entries).
- Float agreement, not part of acceptance: the lowest two levels of the exact matrices at ECUT 60 are
  27.39087855037, 33.82578319642 (λ = 6) and 33.48978484407, 41.29906333928 (λ = 8), the same as the rows of the
  independent float build in `research/2026-11-11/su3_twosquare/results_sweep.csv` to all 12 printed digits.

### (a) Retained space is the complete electric cutoff

P = all (b,c,a,k,l) with `3c(b) + 3c(c) + c(a) ≤ ECUT`, by enumeration with rational Casimirs. Since
`E_el ≥ 3c(b) + 3c(c)`, every state with E_el ≤ ECUT + 6 has `3c(b) + 3c(c) ≤ ECUT + 6`. c(p,q) is strictly
increasing in p and in q, so those irreps lie in a box whose edge is checked (`reps_upto`). All pairs (b,c) in the box,
all a from Racah–Speiser, multiplicity N gives N² states. The same loop returns
c_plus = the smallest electric energy above ECUT, valid over the whole infinite complement because it is ≤ ECUT + 6:
c_plus = 151/3 (ECUT 50) and 181/3 (ECUT 60). Nothing is cut from a larger float basis.

### (c) Coupling bound: the exact B B†, not a norm bound

Version proved: **M = B B† exactly.** `B = P V Q = −λ P S Q`, so in the rational basis
`M = λ² S_PR G_R⁻¹ S_RP`, where R is the set of states outside P that S connects to P. R is complete by construction:
for every block (b,c) containing a retained state the build visits every block pair in which it is the source
(b → b + weight of f, three moves on each arm) and every pair in which it is the target, and inside a pair every
(a,a') with one end in P. R has 917 states at ECUT 50 and 1494 at ECUT 60. 465 and 793 retained states couple out.
The fallback `(V_max/2)² Π` was not needed and is not used.

### (d) A is exact; the inertia count is integer arithmetic

`A = (E + 6λ) G − λ S_PP` and `K(z) = A − zG − M/(d − z)` are exact rational matrices (congruent to the
orthonormal-basis matrices, same inertia). There is no eps and no float matrix in the certificate.

The inertia count replaces the repo's rational LDL, which is too slow at n = 1343, by an exact congruence:

1. `K' = 2^52 · Sc K Sc` with Sc a positive rational diagonal. `Kt = round(K')` entrywise, `|K' − Kt| ≤ 1/2`.
2. A float unpivoted LDL of Kt proposes `X ≈ L⁻ᵀ`. `Xt = round(2^40 X)`, forced upper triangular with diagonal 2^40.
   Xt is an integer matrix with nonzero determinant whatever the floats did.
3. `Y = Xtᵀ Kt Xt` is computed exactly: operands are split into balanced base-2^26 digits, each int64 matrix
   product is bounded by n·2^50 < 2^63 (asserted), sums are Python ints. numpy integer matmul is not BLAS.
4. `Xtᵀ K' Xt = Y + Err`, `|Err_ij| ≤ c_i c_j / 2`, `c_i = Σ_k |Xt_ki|`. Accept only if for every i
   `|Y_ii| > Σ_{j≠i} |Y_ij| + c_i Σ_j c_j / 2`. Then no Gershgorin disc of the symmetric matrix `Xtᵀ K' Xt` contains
   0, and by Sylvester inertia(K) = inertia(Xtᵀ K' Xt) = signs of diag(Y).

If the float proposal were bad the test would fail to conclude; it cannot produce a wrong count. Worst
radius/centre ratios in the accepted runs: 5.0e-6, 4.9e-6, 1.2e-5, 2.4e-5. The count agrees with the repo's
`exact_inertia` (rational LDL) on 7 test matrices built from the new 19-state data, including the repo's own
λ = 1 and λ = 4 targets, which are reproduced.

Theorem 3 is then applied as stated in the paper: z < d, `K_M(z)` has exactly one negative and n − 1 positive
eigenvalues, and A − zG has a negative direction (the trial vector, since r < z).

### (e) Variational upper bound

The float ground vector of the retained problem is rounded to an integer vector x (40 bits). `r_exact = xᵀAx / xᵀGx`
is an exact Fraction from the same exact A and G, and r is r_exact rounded up to 1e-9. x lies in P, so
`E0(H) ≤ r_exact ≤ r`.

## Rigorous versus conditional

Rigorous inside the script (exact integers and rationals): the irreps and intertwiners (verified identities), the
enumeration and c_plus, G, S, A, M = B B†, the one-plaquette floors, r, and the inertia counts. No row is
FLOAT-CONDITIONAL.

Imported, not re-proved here:
- Theorem 3 and its operator-domain statement (paper, section 4).
- The spin-network description of the physical space with `E_el = 3c(b) + 3c(c) + c(a)` (`TWO_PLAQUETTES.md`), and the
  allocation bound (`LOCAL_ENERGY_FLOORS.md`, positivity-improving ground state argument).
- `su3_character_certificate.interval_inertia` for the one-plaquette floors.

Written argument, checked but not machine-proved: the coefficient formula of step 4 above for general blocks with
multiplicity. It is a short Peter–Weyl and Schur-lemma derivation. The script supports it by the exact identities
listed above and by the 12-digit agreement with the independent float build, but those are consistency checks.

Trusted software: CPython integers and Fractions, numpy int64 matrix product and object-array integer operations.
Floats (numpy/scipy `eigh`, a float LDL) only propose the trial vector, the transform Xt and the control energy.

## Weakest link

1. The step-4 coefficient formula is a hand derivation. A reviewer should check it, or it should be formalised; an
   independent exact computation of S on a few multiplicity-2 blocks by Haar integration of degree > 6 would close it.
2. Not Lean. The inertia count leans on numpy integer arithmetic at n = 1343.
3. λ = 8 still loses 0.011 (0.14%) to the boundary at ECUT 60; a larger ECUT should recover most of it (untested;
   the float proposal at ECUT 50 gave 7.676 and at ECUT 60 gave 7.793, so the loss is shrinking fast). Larger λ needs larger ECUT; the exact build costs seconds (5 s at ECUT 60), the n³ integer
   congruence is the bottleneck (about 45 s per count at n = 1343).
